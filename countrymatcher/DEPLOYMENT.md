# Публикация проекта

## Публичная страница

Основной пользовательский интерфейс:

- `https://sankhipkate.github.io/countrymatcher/`

Отдельный лендинг:

- `https://sankhipkate.github.io/countrymatcher/landing/`

Папка `/matcher/` содержит CSS и JavaScript приложения, но не имеет собственной пользовательской HTML-страницы или перенаправления. Прежний `/pilot/` не получает нового публичного адреса.

## Источник публикации

GitHub Pages workflow публикует папку `countrymatcher/` как корень сайта после успешного выполнения тестов.

Рабочий процесс:

1. изменения вносятся в отдельной ветке;
2. запускаются автоматические тесты;
3. создаётся pull request в `main`;
4. после merge GitHub Pages публикует новую версию из папки `countrymatcher/`;
5. проверяются корневой адрес, `/landing/` и отсутствие пользовательской страницы по `/matcher/`.

## Нормативные правила версионирования

`DEPLOYMENT.md` — единственный нормативный документ по присвоению и публикации версии приложения. Техническим источником текущего номера служит файл `VERSION`.

Версия имеет формат `COUNTRIES.FEATURES.FIXES`:

- `COUNTRIES` — количество стран, подключённых к пользовательскому расчёту;
- `FEATURES` — номер крупного изменения анкеты, движка, структуры результата или пользовательских возможностей без добавления страны;
- `FIXES` — номер опубликованного набора исправлений и небольших изменений.

Правила увеличения:

- добавлена страна: `7.1.1` → `8.0.0`;
- добавлена или существенно изменена функция: `7.1.1` → `7.2.0`;
- опубликованы исправления без крупного изменения функции: `7.1.0` → `7.1.1`;
- изменение исследовательских данных, меняющее пользовательский результат, увеличивает `FIXES`;
- изменение внутренних материалов, не меняющее приложение или пользовательский результат, не требует новой версии.

После публикации в `main` номер считается использованным навсегда. Два разных опубликованных состояния проекта не могут иметь одинаковую версию. Номер изменяется до commit и push; commit с пользовательскими изменениями нельзя отправлять в `main` под номером предыдущей публикации.

Одинаковый номер должен быть указан в:

- `VERSION`;
- `package.json` и `package-lock.json`;
- footer интерфейса;
- `README.md` и `DEPLOYMENT.md`;
- cache-key пользовательских JS, CSS, страновых JSON и схем;
- валютном контексте как версия движка.

Служебные самостоятельные компоненты могут иметь собственную версию cache-key только тогда, когда это явно проверяется тестом и не выдаётся за версию приложения.

## Проверка перед merge

```bash
npm ci
npm test
find js matcher pilot -name '*.js' -print0 | xargs -0 -n1 node --check
git diff --check
```

README и этот документ обновляются вместе с изменениями публичных адресов, версии или пользовательского поведения.
