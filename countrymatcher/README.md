# COUNTRY MATCHER

Персональный навигатор переезда для граждан РФ. Одна универсальная анкета формирует профиль `user-profile-v1`, после чего generic Canon 4.0 engine проверяет миграционные маршруты подключённых стран и отдельно формирует практические сведения для выбора страны.

## Рабочая версия

Публичная страница:

- `https://sankhipkate.github.io/countrymatcher/`

Отдельный лендинг:

- `https://sankhipkate.github.io/countrymatcher/landing/`

Версия интерфейса: **8.0.0**.

Нормативные правила присвоения и публикации версии находятся в [`DEPLOYMENT.md`](DEPLOYMENT.md). После публикации в `main` номер версии повторно не используется.

Корневой адрес проекта открывает приложение. Лендинг доступен отдельно по адресу `/landing/`; каталог `/matcher/` хранит ресурсы приложения и не является пользовательской страницей. Прежний `/pilot/` не получает нового публичного адреса.

## Что уже работает

- универсальная анкета формирует профиль `user-profile-v1`;
- активный matcher загружает RP4-пакеты перечисленных ниже активных стран;
- активные страны: Испания, Аргентина, Уругвай, Бразилия, Португалия, Мексика, Парагвай и Колумбия;
- generic Canon 4.0 engine проверяет `requirements[]`, включая финансовые модели, family scenarios, application methods и long-term path;
- маршруты с `publishable: false` исключаются до evaluation;
- анкета доступна без оплаты;
- после расчёта первая страна с лучшим маршрутом `SUITABLE` или `SUITABLE_WITH_CONDITIONS` открывается полностью бесплатно;
- остальные найденные подходящие или условно подходящие страны открываются после подтверждённого полного доступа;
- Quality of Life для активных стран выводится отдельным editorial-слоем после налогового блока и не влияет на matching, статусы или сортировку.

## Контракт активного runtime

- принимаются только `schema_version = 4.0` и `canon_revision = 2026-08-08-final-lock`;
- `requirements[]` — единственный источник статуса маршрута на текущем этапе;
- `DISPLAY_ONLY` не понижает статус, `UNASKED_CONDITION` создаёт условие, `ENGINE` проверяется generic-операторами;
- research gaps не меняют статус автоматически: непубликуемый маршрут исключается через `publishable: false`;
- legacy application, family, goal и `detail_tables` не участвуют в расчёте RP4.0;
- городские расходы используют стандартизированную comparison-корзину и не сравниваются с пользовательским бюджетом;
- школьный блок определяется наличием детей, а не пользовательским выбором типа школы.

## Доход и сбережения в анкете

Для каждого источника дохода пользователь указывает общий регулярный доход и затем выбирает:

- весь доход можно подтвердить;
- можно подтвердить только часть;
- пока доход подтвердить нельзя.

Поле отдельной подтверждаемой суммы появляется только при выборе «Только часть». Пустая подтверждаемая сумма блокирует переход именно на шаге дохода, а не в конце анкеты.

Отдельно собирается общий объём подтверждаемых сбережений, доступных для подачи. Инвестиционный капитал, будущая оферта, зачисление и бизнес-основание не выводятся из суммы сбережений автоматически.

## Доступ к результатам

Расчёт выполняется до проверки оплаты. Если найден хотя бы один подходящий или условно подходящий вариант, первая страна по общей сортировке результата открывается бесплатно целиком.

Полный доступ открывает остальные результаты и возможность менять ответы и пересчитывать анкету. Permanent access token после подтверждённой онлайн-оплаты проверяется серверным Worker и хранится в текущем browser profile. Ручной код доступа после успешной проверки также активирует текущий browser profile. Автоматической синхронизации доступа между разными браузерами или устройствами в версии 8.0.0 нет.

Ответы анкеты и черновик сохраняются только в браузере пользователя.

## Архитектура

- `index.html` — публичная универсальная анкета и результаты;
- `matcher/` — стили и JavaScript публичного приложения без собственной HTML-страницы;
- `matcher/profile.js` — формирование и проверка `user-profile-v1`;
- `matcher/funnel.js` — бесплатный preview и состояния результата до подтверждения полного доступа;
- `js/engine/rp4-engine.js` — единственный активный generic evaluator Research Package 4.0;
- `data/{ES,AR,UY,BR,PT,MX,PY,CO}-research-v4.0.json` — активные Research Package;
- `data/quality-of-life-ru.json` — отдельный presentation-only editorial слой качества жизни;
- `data/*-research-v3.0.json` — архивные инертные исследования, не входящие в runtime;
- `data/research-package-v4.0.schema.json` — текущий контракт Research Package;
- `../source-documents/canon-v4.0/COUNTRY_RESEARCH_STANDARD.md` — единственный действующий стандарт исследования страны;
- `../source-documents/canon-v4.0/MATCHING_AND_RESULT_STANDARD.md` — единственный действующий стандарт сопоставления анкеты, статусов, сортировки и результата в браузере;
- `../source-documents/canon-v4.0/NEW_COUNTRY_RESEARCH_PROMPT.md` — готовое ненормативное задание для запуска исследования новой страны по действующему стандарту;
- `docs/research/` — архивные и вспомогательные материалы исследований стран;
- `data/schemas/user-profile-v1.schema.json` — схема профиля пользователя;
- `tests/` — автоматические проверки движка, профиля, страновых пакетов, funnel, access flow и интерфейса.

Нормативные правила исследования, статусов и пользовательского результата не дублируются в README и находятся только в двух стандартах из списка выше.

## Тестирование

```bash
npm install
npm test
```

GitHub Actions запускает тесты при pull request и push в `main`.

## Публикация

GitHub Pages workflow после успешных тестов публикует папку `countrymatcher/` как корень сайта. После merge обновления публичной анкеты появляются по корневому адресу проекта, а отдельный лендинг — по адресу `/landing/`.

## Правило сопровождения

README обновляется при каждом изменении пользовательского поведения, структуры проекта, версии, подключённых стран или публичных адресов. Изменение считается незавершённым, если код обновлён, а README больше не описывает фактическое состояние проекта.
