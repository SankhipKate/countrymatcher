# Country Matcher 4.0 — решение по непроверяемым основаниям и требованиям

Версия: 4.0

Дата: 2026-08-08

Для канона 4.0 зафиксирована следующая граница:

1. Самостоятельное основание маршрута, которого нет в анкете (например, оферта, зачисление, бизнес-проект, инвестиционное основание, специальная семейная связь, индивидуальное основание защиты), по умолчанию считается ещё не полученным для расчёта и создаёт `condition`.
2. Если анкета уже подтверждает существующую работу или доход, не спрашиваемые срок этой работы/дохода, длительность отношений с текущим работодателем/заказчиком, срок деятельности текущего работодателя/заказчика и обычные подтверждения этого существующего основания не считаются отсутствующими и не понижают статус. Они показываются как требования к подготовке подачи.
3. Диплом/образование и профессиональный опыт анкета 4.0 намеренно не проверяет. Если маршрут требует диплом, определённое образование или минимальный опыт/стаж, эти факты не считаются отсутствующими и не понижают статус; они показываются в требованиях к подаче. Это действует и для составного требования «образование ИЛИ N лет опыта».
4. Профессия, официальное признание квалификации и лицензия могут оставаться условиями только когда маршрут требует именно получить новый юридический/профессиональный допуск.
5. Для DNV контрольный пример обязателен: при подтверждённой удалённой работе и достаточном доходе требования о сроке деятельности компании, длительности отношений с работодателем/заказчиком и «образование ИЛИ N лет опыта» являются требованиями к подаче (`DISPLAY_ONLY`), а не `condition`.
6. Для учебного маршрута анкета не спрашивает, поступил ли пользователь. Поэтому для расчёта 4.0 зачисление по умолчанию считается ещё не полученным и создаёт `condition`.

Эта правка меняет нормативные документы и research prompt. Schema не требует нового enum: существующие `UNASKED_CONDITION` и `DISPLAY_ONLY` достаточны для этой модели.


## Final Lock 4.0 invariants

- `open_items`, исследовательские пробелы и отсутствие вспомогательной информации сами по себе не создают `SUITABLE_WITH_CONDITIONS`.
- `SUITABLE_WITH_CONDITIONS` допустим только при хотя бы одном реальном пользовательском `condition`; пустой список conditions при этом статусе является ошибкой движка.
- Для финансовой модели `unmet_effect` применяется после оценки всей модели, а не после провала одной альтернативы.
- `ONLINE` — канал/этап, не самостоятельное место подачи.
