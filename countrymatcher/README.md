# COUNTRY MATCHER

Персональный навигатор переезда для граждан РФ. Одна универсальная анкета формирует профиль `user-profile-v1`, после чего generic Canon 4.0 engine проверяет миграционные маршруты подключённых стран и отдельно формирует практические сведения для выбора страны.

## Рабочая версия

Публичная страница:

- `https://sankhipkate.github.io/countrymatcher/`

Отдельный лендинг:

- `https://sankhipkate.github.io/countrymatcher/landing/`

Текущий номер интерфейса хранится только в [`VERSION`](VERSION) и подставляется в публикуемый интерфейс при сборке. Нормативные правила присвоения и публикации версии находятся в [`DEPLOYMENT.md`](DEPLOYMENT.md). После публикации в `main` номер версии повторно не используется.

Корневой адрес проекта открывает приложение. Лендинг доступен отдельно по адресу `/landing/`; каталог `/matcher/` хранит ресурсы приложения и не является пользовательской страницей. Прежний `/pilot/` не получает нового публичного адреса.

## Что уже работает

- универсальная анкета формирует профиль `user-profile-v1`;
- активный matcher загружает RP4-пакеты перечисленных ниже активных стран;
- активные страны: Испания, Аргентина, Уругвай, Бразилия, Португалия, Мексика, Парагвай, Колумбия, Черногория, Чили, Греция, Коста-Рика и Эквадор;
- generic Canon 4.0 engine проверяет `requirements[]`, включая финансовые модели, family scenarios, application methods и long-term path;
- маршруты с `publishable: false` исключаются до evaluation;
- узкоспециализированные самостоятельные family/ICT/corporate/maritime routes сохраняются в research inventory, но не публикуются как пользовательские route cards; family scenarios внутри обычных основных маршрутов сохраняются;
- анкета доступна без оплаты;
- после расчёта одна страна с маршрутом `SUITABLE` или `SUITABLE_WITH_CONDITIONS` открывается полностью бесплатно; если полностью подходящих стран несколько, выбирается страна с наибольшей суммой мест по сроку до гражданства и порогу дохода;
- остальные найденные подходящие или условно подходящие страны открываются после подтверждённого полного доступа;
- Quality of Life для активных стран выводится отдельным editorial-слоем после налогового блока и не влияет на matching, статусы или сортировку.
- для стран с настроенной коллаборацией после Quality of Life может показываться отдельный presentation-only блок миграционного консультанта; сейчас для Черногории подключён ResidencyNow с переходом в Telegram и заранее подготовленным сообщением.

## Контракт активного runtime

- принимаются только `schema_version = 4.0` и `canon_revision = 2026-08-08-final-lock`;
- `requirements[]` — единственный источник статуса маршрута на текущем этапе;
- `DISPLAY_ONLY` не понижает статус, `UNASKED_CONDITION` создаёт условие, `ENGINE` проверяется generic-операторами;
- research gaps не меняют статус автоматически: непубликуемый маршрут исключается через `publishable: false`;
- legacy application, family, goal и `detail_tables` не участвуют в расчёте RP4.0;
- городские расходы используют стандартизированную comparison-корзину и не сравниваются с пользовательским бюджетом;
- школьный блок определяется наличием детей, а не пользовательским выбором типа школы.

## Доход и сбережения в анкете

Для каждого источника дохода пользователь указывает общий регулярный доход и затем выбирает:

- весь доход можно подтвердить;
- можно подтвердить только часть;
- пока доход подтвердить нельзя.

Поле отдельной подтверждаемой суммы появляется только при выборе «Только часть». Пустая подтверждаемая сумма блокирует переход именно на шаге дохода, а не в конце анкеты.

Отдельно собирается общий объём подтверждаемых сбережений, доступных для подачи. Этот денежный факт может использоваться и для capital screening, если research конкретного маршрута требует просто иметь доступную сумму. Уже совершённая инвестиция, специальный актив, paid-up company capital, будущая оферта, зачисление, инвестиционное намерение и бизнес-основание из суммы сбережений автоматически не выводятся.

## Доступ к результатам

Расчёт выполняется до проверки оплаты. Если найден хотя бы один подходящий или условно подходящий вариант, одна страна открывается бесплатно целиком. При нескольких полностью подходящих странах бесплатной становится страна с наибольшей суммой мест по сроку до гражданства и порогу дохода. Если полностью подходящая страна одна, результат объясняет текущее ограничение и показывает ближайший подтверждённый порог, при котором появляются дополнительные полностью подходящие страны.

Полный доступ открывает остальные результаты и возможность менять ответы и пересчитывать анкету. Permanent access token после подтверждённой онлайн-оплаты проверяется серверным Worker и хранится в текущем browser profile. Ручной код доступа после успешной проверки также активирует текущий browser profile. Автоматической синхронизации доступа между разными браузерами или устройствами нет.

До оплаты верхний итог показывает две плашки: полностью подходящие страны и маршруты, а также все подключённые страны и потенциальные маршруты с условиями или отдельным основанием. Бесплатный разбор одной страны показан полностью. Для нескольких полностью подходящих стран выводится сравнение по сроку до гражданства и порогу дохода; для единственной полностью подходящей страны — блок «Что вас сейчас ограничивает». Ниже идут продающий блок, отзывы, FAQ, встроенная оплата с альтернативными способами, активация по готовому коду, подписка и юридические ссылки.

Ответы анкеты и черновик сохраняются только в браузере пользователя.

## Архитектура

- `index.html` — публичная универсальная анкета и результаты;
- `matcher/` — стили и JavaScript публичного приложения без собственной HTML-страницы;
- `matcher/profile.js` — формирование и проверка `user-profile-v1`;
- `matcher/funnel.js` — бесплатный preview и состояния результата до подтверждения полного доступа;
- `js/engine/rp4-engine.js` — единственный активный generic evaluator Research Package 4.0;
- `data/{ES,AR,UY,BR,PT,MX,PY,CO,ME,CL,GR,CR,EC}-research-v4.0.json` — активные Research Package;
- `data/quality-of-life-ru.json` — отдельный presentation-only editorial слой качества жизни;
- `data/country-consultants-ru.json` — country-configured presentation-only коллаборации с миграционными консультантами; они не участвуют в matching, статусах или сортировке;
- `matcher/consultants.js` — generic helper для выбора активных консультантов страны и формирования outbound Telegram URL;
- `data/*-research-v3.0.json` — архивные инертные исследования, не входящие в runtime;
- `data/research-package-v4.0.schema.json` — текущий контракт Research Package;
- `../source-documents/canon-v4.0/COUNTRY_RESEARCH_STANDARD.md` — единственный действующий стандарт исследования страны;
- `../source-documents/canon-v4.0/MATCHING_AND_RESULT_STANDARD.md` — единственный действующий стандарт сопоставления анкеты, статусов, сортировки и результата в браузере;
- `../source-documents/canon-v4.0/NEW_COUNTRY_RESEARCH_PROMPT.md` — готовое ненормативное задание для запуска исследования новой страны по действующему стандарту;
- `docs/research/` — архивные и вспомогательные материалы исследований стран;
- `data/schemas/user-profile-v1.schema.json` — схема профиля пользователя;
- `tests/` — автоматические проверки движка, профиля, страновых пакетов, funnel, access flow и интерфейса.

Нормативные правила исследования, статусов и пользовательского результата не дублируются в README и находятся только в двух стандартах из списка выше.

## Тестирование

Каноническая полная локальная проверка запускается одной командой из корня репозитория:

```bash
bash ./verify
```

Корневой `verify` — тонкая обёртка: она находит проект относительно собственного файла и передаёт выполнение единственному внутреннему verifier. Поэтому проверка не зависит от текущего каталога вызывающего и работает также в распакованном архиве без `.git`; в таком режиме пропускаются только Git-specific проверки.

Verifier сам выполняет чистый `npm ci`, подготавливает изолированное Python-окружение для RP4 validator, валидирует все RP4-пакеты, запускает полный Node test suite и проверяет синтаксис JavaScript. В Git worktree дополнительно выполняются проверки незакоммиченного, staged и последнего committed diff. Обычный `npm test` также автоматически восстанавливает отсутствующие или рассинхронизированные Node dependencies перед запуском тестов. Прямой `node --test` не является release gate, потому что обходит этот dependency bootstrap.

GitHub Actions при pull request и push в `main` использует тот же корневой verifier.

## Публикация

GitHub Pages workflow после успешных тестов публикует папку `countrymatcher/` как корень сайта. После merge обновления публичной анкеты появляются по корневому адресу проекта, а отдельный лендинг — по адресу `/landing/`.
